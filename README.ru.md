# agent-stack

**Сохраняй рабочие правила при смене агента.**

Проверенные инструкции, навыки и шаблоны для **Hermes, OMP и Codex**. Общая библиотека поведения переносится между агентами; ключи, настройки runtime и живые сессии остаются у своего владельца.

Каждый компонент имеет явные targets и ограничения в [manifest.yaml](manifest.yaml). Общие targets означают возможность установить один текст навыка в разные runtime. Одинаковое поведение моделей и наличие одинаковых инструментов проверяются отдельно.

## Что переносится

| Общие материалы | Остаётся у runtime и host |
| --- | --- |
| Инструкции проверки результата | Ключи, OAuth и другие credentials |
| Выбранные навыки с явными targets | Настройки моделей, провайдеров и MCP |
| Пустые шаблоны передачи работы | Сессии, журналы, расписания и базы данных |
| Проверенные рабочие правила | Профиль, настройки машины и приватные знания |

Репозиторий переносит материалы поведения. Он не обновляет Hermes, OMP, Codex или Jev, не заменяет их конфигурацию и не синхронизирует сессии. Автоматических pull, push и deploy здесь нет.

## Сначала предпросмотр

Нужен **Python 3.12+**. Из корня репозитория выведи базовые компоненты без записи:

```sh
python installers/install.py hermes --dry-run
# вместо hermes можно выбрать omp или codex
```

Обёртки для своей платформы: `./installers/install.sh codex` или `./installers/install.ps1 codex` в PowerShell.

Для проверки выбранного навыка укажи существующий абсолютный корень нужного профиля. В примере `HERMES_HOME` должен быть задан заранее:

```sh
./installers/install.sh hermes \
  --component proof-gated-coding-delivery \
  --destination "$HERMES_HOME" \
  --no-clobber \
  --dry-run
```

После проверки плана и разрешения на установку замени `--dry-run` на `--apply`.

- Для записи обязательны `--component` и `--destination`.
- Destination — корень выбранного runtime/профиля, вне этого репозитория и исходников runtime.
- `--no-clobber` запрещает замену существующих targets. Без destination коллизии на диске не проверяются.
- Намеренная замена без `--no-clobber` сохраняет предыдущую версию в резервной копии; восстановление выполняется вручную.
- Компоненты `optional` выбираются явно. Фрагменты `manual` объединяются с инструкциями вручную, установщик их не применяет.

Подробнее: [переносимость и восстановление](docs/portability.md).

## Выбери компоненты

| Компонент | Targets | Подключение |
| --- | --- | --- |
| `verification` | Hermes / OMP / Codex | Проверенные инструкции; копирование не включает их автоматически |
| `proof-gated-coding-delivery` | Hermes / OMP / Codex | Разделяет реализацию, проверку в runtime и готовность к выпуску |
| `knowledge-combine` | Hermes / OMP / Codex | Необязательное объединение знаний; место хранения выбирает пользователь |
| `handoff-template` | Hermes / OMP / Codex | Пустой шаблон передачи работы |
| `ecc-context-budget` / `ecc-workflow-eval` | Hermes / OMP | Выборочные адаптации ECC с отдельными офлайн-проверками |
| `personal-operator-baseline` | Только Hermes | Правила работы, специфичные для Hermes |
| `hermes-soul-fragment` / `codex-agents-fragment` | Соответствующий runtime | Ручное объединение с существующими инструкциями |
| `design-reference-loop` | Hermes / OMP / Codex | Бриф → референсы → концепции → выбор → реализация → проверки |
| 29 [дизайн-навыков](design/README.md) | Hermes / OMP / Codex | Общие статические адаптации Taste, Emil и Impeccable, устанавливаются по выбору |
| `design-routing-fragment` | Hermes / OMP / Codex | Ручное добавление правил выбора дизайн-навыков |

Все **30 дизайн-навыков** находятся в `shared/skills` и имеют статус `optional`. Например, один и тот же компонент можно посмотреть для любого из трёх runtime:

```sh
python installers/install.py hermes --component impeccable-design --dry-run
python installers/install.py omp --component impeccable-design --dry-run
python installers/install.py codex --component impeccable-design --dry-run
```

Генерация изображений, браузер, subagents и другие возможности предоставляются самим host. Если инструмента нет, навык должен обозначить ограничение. `prototype`, `pick-ui-library` и `review-animations` сохраняют явный вызов во всех runtime. Impeccable содержит только статические правила, без движка и hooks.

Статусы, destinations, зависимости и `tested_on` определяются [manifest](manifest.yaml). `reviewed` означает проверку материалов, `optional` — явный выбор, `manual` — ручное объединение. Пустой `tested_on` не доказывает проверку внутри агента.

## Установка и работа агента проверяются отдельно

Тесты выполняют выборочную установку в одноразовые каталоги и сверяют хеши файлов. Это не подтверждает обнаружение навыка в уже открытом чате, соблюдение инструкций моделью или улучшение качества.

Для ECC отдельно записаны проверки обнаружения и чтения через OMP и Windows Hermes: [результаты и ограничения](docs/portability.md#selective-ecc-adaptations). Новый процесс OMP видел ресурсы, а уже открытая беседа не подхватила их. Установка файлов и обновление каталога текущей беседы — разные события.

Необязательный [нативный эксперимент ECC для OMP](runtimes/omp/README.md#native-ecc-trial-ecc-safe) использует закреплённый Pi adapter в отдельном профиле. Его PowerShell launcher сохраняет дополнительные правила и lifecycle scripts выключенными. Это отдельный эксперимент, без замены обычной конфигурации OMP.

## Продолжить в Codex Cloud

Создай облачное environment для `typakon4/agent-stack`, используй актуальный `master` и передай контекст из [инструкции Codex Cloud](docs/codex-cloud.md). Там есть проверки, пример выборочного подключения skills и готовый текст для новой задачи. Личные навыки и процессы этого компьютера в Cloud автоматически не переносятся.

## Безопасность и владельцы настроек

Предпросмотр и установка проверяют имена исходных файлов и очевидные сигнатуры credentials, не печатая найденные значения. Этот контроль не гарантирует обнаружение всех секретов; исходники и diff также проверяются вручную.

Не добавляй ключи, браузерные профили, приватные знания, сырой экспорт переписки или состояние runtime. Авторизованный инструмент не даёт разрешения публиковать, отправлять сообщения, покупать, удалять или развёртывать. Подробнее: [границы безопасности](docs/security.md).

Jev остаётся **внешней зависимостью**, закреплённой на `08473a5496864e8c97ee6f8f58980131ae16aed2`. Его исходники, MCP-конфигурация, credentials и replay сюда не входят. Дизайн-проверщик работает офлайн; live-адаптер выбора концепций не подключён. См. [интеграцию Jev](integrations/jev/README.md).

## Проверки

```sh
python -B tests/validate_manifest.py
python -B -m unittest discover -s tests -v
python -B -m unittest discover -s design/tests -v
```

GitHub Actions запускает проверки на Linux и Windows с Python 3.12 и 3.14, а также предпросмотры нативных установщиков. Проверяются manifest, хеши дизайн-навыков, выборочная установка, ограничения путей и очевидные секреты в файлах и истории Git. Тесты используют одноразовые runtime homes. Поведение моделей, визуальное качество и работа реального Jev оцениваются отдельно.

## Добавить навык или runtime

Проверь необходимые инструменты, происхождение, лицензии и границы доступа/публикации. Укажи source, явные targets и статус в manifest, затем выполни предпросмотр для согласованного destination. Сохраняй native policy вместо замены всей конфигурации. См. [архитектуру](docs/architecture.md).

Пять базовых коммитов сохранены в истории; устаревшие Hermes-only файлы отсутствуют в текущем дереве.
