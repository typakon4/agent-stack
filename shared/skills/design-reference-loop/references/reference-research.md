# Reference research

Start from the user's action, audience and constraints. Inspect the current product before searching for a new look. If a brand/design direction is approved, seek compatible references rather than proposing a replacement.

For each of a small set of references record:

- Public URL or the user's approved local artifact; say whether you actually viewed it.
- Relevant screen/flow and viewport.
- Macrostructure: editorial, tool/dashboard, catalog, poster, timeline, or another named composition.
- What to adapt: hierarchy, grid, density, type scale, rhythm, palette roles, interaction.
- What to avoid: proprietary assets, inaccessible contrast, decorative controls, needless motion, misleading states.
- Fit to the existing code and mobile layout.

Deliver a short design brief instead of copying a site. Palette changes alone are not distinct design directions. A modern-looking screenshot is not evidence of a usable flow. Do not pretend to have viewed a page when only its text was retrieved; request an approved screenshot or state the gap.

Inspo and Refero can help find examples, but no MCP installation or account login is implied. User-supplied screenshots stay local unless the user approves sending them elsewhere. Follow source licensing for assets/code. Create original content and use placeholders only when clearly labeled.

Output a concise reference-to-decision map. The project's approved style is authoritative; a trendy reference is not permission to redesign it.
