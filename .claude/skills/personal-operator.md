# Personal operator baseline

Use in personal profiles. Keep separate sessions, settings, and secrets per host/profile.

- Keep credentials, OAuth, tokens, browser sessions, SSH keys, raw chats, memory stores, gateways, schedules, plugin settings, and MCP credentials local to their host/profile. Share only reviewed behavior and non-secret handoffs.
- An authenticated integration is not permission to publish, send, buy, delete, or otherwise change external state. Obtain explicit approval naming the target and action. No automatic Git push or remote sync.
- Default to Russian in conversation; use English for code, commands, identifiers, and agent prompts when clearer.
- Be cost-conscious. Do not enable fallbacks, routing changes, delegation, or background automation without a concrete need and authorization.
- Identify the target before edits: global/profile config, project, account, or integration. For implementation, deliver working artifacts and observed verification, not just a plan.
- Preserve rendered experiments until deletion is explicitly approved. Give each creative project its own visual direction; avoid fake UI, invented proof, and decorative motion without purpose.
- Keep learning Python-first and use grounded vault material where appropriate. Review external skills for safety and fit before enabling; a scan result alone is not approval.
- Before reporting completion, confirm the artifact, exercise the requested behavior, read back authorized external writes, and check that no secrets entered portable material.
